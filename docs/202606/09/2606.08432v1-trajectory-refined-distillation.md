## 摘要
在线策略蒸馏（OPD）已成为大型语言模型（LLM）的核心后训练工具，它在学生模型自身的轨迹生成过程中提供密集的逐token教师监督。在本文中，我们识别了OPD中一个常见的结构性问题，称为前缀失败。在前缀失败下，密集的逐token监督会导致双峰教师混合和碎片化梯度，而token级损失截断或重加权无法解决这一问题。这一观察促使我们超越token级损失干预，转向轨迹级输出修正。因此，我们提出了轨迹精炼蒸馏（TRD），一种轨迹级修正方法，它在教师指导下修正学生模型的轨迹生成，同时保持在在线策略支持范围内。通过在蒸馏前修正有问题的前缀，TRD从根源上缓解了前缀失败。此外，TRD通过让学生暴露在教师指导下的替代有效推导中改善探索，即使原始轨迹已经正确。TRD也可应用于在线策略自蒸馏（OPSD），这是一种参数共享变体，使用以特权信息为条件的学生模型作为教师。在多种基准测试和多个尺度的基础模型上，TRD始终优于先前的基线，提高了单次尝试准确率并拓宽了推理覆盖范围。代码可在https://github.com/louieworth/trd获取。

## Abstract
On-policy distillation (OPD) has become a central post-training tool for large language models (LLMs), providing dense per-token teacher supervision along the student's own rollouts. In this work, we identify a common structural cause underlying OPD, which we call prefix failure. Under prefix failure, dense per-token supervision induces a bimodal teacher mixture and fragmented gradients that token-level loss truncation or reweighting fail to address. This observation motivates us to move beyond token-level loss interventions toward trajectory-level output corrections. We thus propose Trajectory-Refined Distillation (TRD), a trajectory-level correction method that revises the student's rollout under the teacher guidance while within on-policy support. By correcting problematic prefixes before distillation, TRD mitigates prefix failure at its source. Moreover, TRD improves the exploration by exposing the student to alternative valid derivations under teacher guidance, even when the original rolls are already correct. TRD can also be applied to on-policy self-distillation (OPSD), a parameter-sharing variant that uses the student model conditioned on privileged informations as the teacher. Across a wide range of benchmarks and base models at multiple scales, TRD consistently outperforms prior baselines, improving single-attempt accuracy and broadening reasoning coverage. Code is available at https://github.com/louieworth/trd

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：在线策略蒸馏（OPD）是 LLM 后训练的重要步骤，利用学生自身轨迹生成时的密集逐 token 教师监督信号。然而，近期研究发现 OPD 的效果常不如预期，存在监督信号噪声大、甚至无信息的问题。
- **识别的核心问题**：作者首次系统阐述了**前缀失败（Prefix Failure）**——当学生的采样路径在前缀阶段就出现错误时，后续几乎无法在不回溯或反思的情况下通过该路径得到正确答案。此时，教师分布变成双峰混合（延续错误前缀 vs. 切换到纠正路径），而逐 token KL 散度沿学生冻结的轨迹给出碎片化梯度，导致监督信号与实际需要的纠正路径不一致。
- **现有方法的不足**：已有的补救方法（如 token 级损失截断、重加权）只操作在 token 损失层面，未改变失败前缀本身，因此无法有效缓解前缀失败。RLVR（强化学习+可验证奖励）提供稀疏的轨迹级奖励，但样本效率差；SFT 使用离线数据，缺少在线结构。因此，需要一种轨迹级的纠正方法。

## 2. 方法论：核心思想、技术细节、算法流程

- **核心思想**：提出轨迹精炼蒸馏（TRD），**在在线策略支持范围内**，由教师指导修正学生原始轨迹，再用修正后的精炼轨迹（$y_r$）进行密集的逐 token KL 蒸馏。这样既保留了 on-policy 特性，又从根源上避免前缀失败，同时即使原始轨迹正确，也能让学生接触教师提供的其他有效推导，提升探索和泛化。
- **技术细节**：
  - **精炼轨迹生成**：对于每个问题-参考解对 $(x, y^*)$，先采样学生原始轨迹 $y_o \sim \pi_\theta(\cdot|x)$，然后让教师以 $y_o$ 和 $y^*$ 为条件生成精炼轨迹 $y_r \sim q(\cdot|x,\cdot)$。在 OPD 中教师是独立的大模型；在 OPSD 中教师是同一模型但条件包含 $y^*$。
  - **蒸馏损失**：使用沿 $y_r$ 的**全词汇前向 KL 散度**（mode-covering 性质），提供稳定的监督信号：
    $$ L(\theta) = \mathbb{E}_{x \sim D, y_o \sim \pi_\theta, y_r \sim \pi_T(\cdot|x,y_o)} \left[ \frac{1}{|y_r|} \sum_{t=1}^{|y_r|} D_{\text{KL}}\big( \text{sg}[\pi_T(\cdot|x,y_r_{<t})] \big\| \pi_\theta(\cdot|x,y_r_{<t}) \big) \right] $$
    其中 $\text{sg}$ 为停止梯度操作（仅 OPSD 中对教师分支使用）。
  - **算法流程（Algorithm 1）**：
    1. 从训练集中采样一个小批 $(x, y^*)$。
    2. 学生采样原始轨迹 $y_o \sim \pi_\theta(\cdot|x)$。
    3. 教师（OPD 中为独立模型，OPSD 中为同一模型条件化 $y^*$）精炼得到 $y_r \sim \pi_T(\cdot|x,y_o)$。
    4. 用 $y_r$ 上的前向 KL 损失更新学生参数 $\theta$。
    5. 重复直至收敛。

- **与 token 级方法的区别**：TRD 不直接在 $y_o$ 上计算 KL，而是先修正轨迹，使后续的逐 token 监督上下文沿纠正路径生长，恢复理想的梯度结构 $g_{\text{ideal}}$。

## 6. 主要结论与发现

- **TRD 在所有实验设置中平均性能最佳**：在 OPD 和 OPSD 下，TRD 的 Avg@16 和 Pass@16 在 5 个数学基准上均优于或持平于最佳基线，且在困难基准（AMOBench）上提升最大。

## 7. 优点

- **理论深度**：首次形式化“前缀失败”并分析其与 KL 方向、梯度碎片化的关系，为 OPD 失败提供了结构性解释。
- **方法的简洁性与有效性**：TRD 仅需额外一次教师精炼生成，不改变蒸馏损失形式，即可显著提升性能，且容易集成到现有 OPD/OPSD 流程中。
- **缓解探索-利用矛盾**：同时处理了失败轨迹（利用教师修正）和成功轨迹（提供备选路径），因此在不破坏已有能力的情况下扩展了解空间。
- **通用性**：可应用于 OPD 和 OPSD 两种设置，在数学和代码任务上均取得改进，并在不同规模模型上一致有效。
- **实证充分**：通过多个诊断实验（Fig.3、Fig.4）验证了精炼轨迹对前缀失败的缓解作用，支撑方法有效性。

## 8. 不足与局限

- **额外采样成本**：TRD 需要额外一次教师精炼生成 $y_r$，在部分设置（如 Qwen3-1.7B OPD）中总时间比基线多约 75%。尽管在更大的骨干上（如 Qwen3-8B OPSD）通过更短的训练轨迹抵消了大部分开销，但小模型场景下计算成本仍需关注。
- **依赖教师能力**：精炼质量取决于教师能否在保持 on-policy 支持的前提下有效纠正前缀失败。如果教师本身能力不足或产生严重偏离学生分布的修正，会限制 TRD 的收益。论文指出使用更强教师可以缓解，但会增加计算负担。
- **代码基准提升有限**：在 LiveCodeBench 上，所有方法（包括 TRD）均未能超过基础模型，说明当前教师对复杂代码任务的精炼尚不够有效。
- **OPSD 下代码评估缺失**：论文仅在 OPD 设置中报告了代码结果，未提供 OPSD 场景下的代码生成实验，限制了结论的通用性。
- **实际部署需要考虑带宽**：精炼生成要求教师模型可用，增加了推理带宽和内存压力，尤其在生产环境中。
- **实验可重复性**：论文提供了代码仓库和部分超参数，但未详细给出所有随机种子和实验运行次数，可能影响统计显著性判断。
