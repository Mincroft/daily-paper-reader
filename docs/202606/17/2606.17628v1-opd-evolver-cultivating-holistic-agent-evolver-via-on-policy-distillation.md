## 摘要
记忆已成为自进化智能体的标准基板，但保留经验并不等同于学习如何通过经验进化。现有的记忆智能体可以存储轨迹、检索反思或积累技能，但往往缺乏选择有用经验、据此行动、编写可复用知识以及维护不断增长的存储库的整体能力。我们提出了OPD-Evolver，一个通过在线策略自蒸馏培养此类智能体进化器的慢-快协同进化框架。在快循环中，OPD-Evolver与四级记忆层次结构交互，以读取、使用、编写和维护经验，实现快速的测试时进化。在慢循环中，结果校准的记忆归因和特权后见之明将这些四种能力蒸馏到可部署的策略中。跨多个领域基准测试，OPD-Evolver超越了像ReasoningBank这样的记忆系统高达11.5%，以及像Skill0这样的基于训练的方法约5.8%。进一步分析表明，OPD-Evolver内化了高价值经验和记忆管理，使OPD-Evolver-9B能够挑战像Qwen3.5-397B-A17B和Step-3.5-Flash这样的庞然大物，指向超越记忆增强型智能体，迈向真正合格的智能体进化器。

## Abstract
Memory has become a standard substrate for self-evolving agents, yet retaining experience is not the same as learning how to evolve through it. Existing memory agents can store trajectories, retrieve reflections, or accumulate skills, but often lack the holistic competence to select useful experience, act on it, write reusable knowledge, and maintain a growing repository. We introduce OPD-Evolver, a slow-fast co-evolution framework that cultivates such an agent evolver through on-policy self-distillation. In the fast loop, OPD-Evolver interacts with a four-level memory hierarchy to read, use, write, and maintain experience for rapid test-time evolution. In the slow loop, outcome-calibrated memory attribution and privileged hindsight distill these four abilities into the deployable policy. Across multi-domain benchmarks, OPD-Evolver surpasses memory systems such as ReasoningBank by up to 11.5%, and training-based methods such as Skill0 by ~5.8%. Further analysis shows that OPD-Evolver internalizes high-value experience and memory management, enabling OPD-Evolver-9B to challenge giant counterparts such as Qwen3.5-397B-A17B and Step-3.5-Flash, pointing beyond memory-augmented agents toward genuinely qualified agent evolvers.

## 2. 方法论

### 核心思想
提出 **OPD-Evolver** 框架，包含两个循环：
- **快循环（Fast Loop）**：智能体在测试时通过四级记忆层次结构（轨迹、技巧、技能、工具）进行在线经验读取、使用、写入和维护，实现快速进化（不更新参数）。
- **慢循环（Slow Loop）**：通过结果校准的记忆归因（outcome-calibrated attribution）和特权后见之明（privileged hindsight），将快循环中产生的行为蒸馏到可部署策略中，使模型学习如何选择、使用、写入和管理经验。

### 关键技术细节
1. **四级记忆层次**：
   - `M_traj`：完整轨迹（忠实但冗长）
   - `M_tip`：局部警告或启发式规则
   - `M_skill`：可复用流程（抽象思路）
   - `M_tool`：可执行命令或代码模板
2. **快循环流程**：
   - 检索：对当前任务查询，从各层检索 Top-K 候选记忆。
   - 选择：由智能体策略 `Sel_θ` 从候选中选出任务相关记忆，形成上下文 `c_t`。
   - 执行：策略 `πθ` 以 `c_t` 和交互历史为条件生成动作。
   - 写入：根据结果，策略决定写入哪些新记忆（各层均可），以及是否进行存储库维护（合并/删除）。
3. **慢循环——结果校准归因**：
   - 对每个记忆 `m`，比较它被选中（`S_t`）和未被选中但被检索（`C_t`）时任务收益的期望差，结合置信度因子计算得分 `V(m)`，作为教师信号。
4. **统一事后自蒸馏**：
   - 对四种能力（选择、执行、写入、维护），分别提供特权信息（如记忆得分、成功轨迹、预期效用等）。
   - 学生模型在自身 roll out 路径上采样输出，教师模型基于学生前缀和特权信息生成目标分布，通过逐 token KL 散度进行蒸馏损失 `L_slow`。

### 公式与算法（文字说明）
- 归因得分：`V(m) = α * γ * (E[R|m入选] - E[R|m未入选])`，其中 γ 为置信因子，α 为层次先验。
- 蒸馏损失：对所有四种决策类型 `k`，在学生自主生成的 tokens 上计算教师分布与学生分布的 KL 散度之和。
- 算法流程：快循环在线积累经验 → 慢循环根据日志估计记忆价值 → 构造 (zk, hk) 对 → 用 OPD 优化策略参数。

## 3. 实验设计

### 数据集/场景与基准
- **LifelongAgentBench**：DB（数据库）和 OS（操作系统）子集，各 100 个测试任务。
- **MemoryArena**：Math（354 任务）和 Physics（86 任务）子集，多会话推理。
- **AMA-Bench**：Causal Inference、State Updating、State Abstraction 三个类别，共 208 个 episode, 2496 个 QA。
- **InterCode**：Bash（224）、CTF（100）、SQL（314）子集，交互式编码。
- **MiniHack**：Room、Maze、KeyRoom 三个环境，各 51 个测试任务，网格导航。
- 训练数据：来自 Agent World Model、Nemotron-Terminal-Corpus、EnvScaler，共 7000 个交互任务，与评估基准不重叠。

### 对比方法
- **记忆增强型**：ExpeL、AWM、Cheatsheet、MemP、ReasoningBank、EvolveR、MemEvolve。
- **训练型**：SFT、GRPO、Skill0、MemRL、Complementary RL。
- **大模型**：Qwen3.5-397B-A17B、Step-3.5-Flash（196B）。
- 所有记忆方法从空存储库开始，按测试流序贯积累经验。

### 主要结果
- OPD-Evolver-4B/9B 在全部 10 个子集上超越同骨干的最强记忆基线（如 ReasoningBank 提升 11.5%）。
- OPD-Evolver-9B 在 9/10 子集上超越 Step-3.5-Flash（196B），在 6/10 上超越 Qwen3.5-397B-A17B。
- 训练型对比：在 5/6 子集上获得最好（优于 GRPO、Skill0、MemRL、Complementary RL）。

### 消融实验
- 移除慢进化、记忆归因、选择蒸馏、写入蒸馏、维护训练分别导致性能下降，其中记忆归因影响最大（平均下降约 6.5 个百分点）。
- 分析显示选择蒸馏后记忆得分分布整体提高，写入蒸馏后记忆得分更集中且更高。
- 经验内化分析：蒸馏后模型即使不用外部记忆，任务成功率和步骤效率也均提升。

## 6. 主要结论与发现
